#+TITLE: emacshell design
#+OPTIONS: toc:2

Runtime architecture and the reasoning behind it.  BUILD.org covers
the build pipeline; this covers what the built artifact does.

* One application, two provenances

An Android APK has exactly one =android:name= Application class, one
launcher activity, one process (per =android:process= default).  GNU
Emacs and Termux each ship their own Application class with required
initialization:

- =org.gnu.emacs.EmacsApplication=: set up the Emacs system thread
  (signal mask), locate the APK file (for the asset manager and dump
  file logic), find any existing portable dump;
- =com.termux.app.TermuxApplication=: install the Termux crash
  handler, apply the persisted log level.

Neither can simply be dropped: =EmacsApplication= is =final= (upstream
does not want it subclassed), and Termux alone leaves Emacs
uninitialized.  =tech.khalidrafi.emacshell.EmacshellApplication=
therefore extends =android.app.Application= directly and replicates
both bodies verbatim, in an order that keeps every upstream invariant:

#+BEGIN_EXAMPLE
super.onCreate ()
TermuxCrashUtils.setCrashHandler (this)        -- first, so later
                                                 failures are reported
setLogLevel ()                                  -- Termux prefs
EmacsNative.setupSystemThread ()                -- Emacs native setup
EmacsApplication.apkFileName = findApkFile ()   -- replicated private
EmacsApplication.findDumpFile (this)            -- already public
installUserInitFiles ()                         -- before any activity
registerActivityLifecycleCallbacks (this)       -- bootstrap trigger
#+END_EXAMPLE

The APK-file lookup is replicated rather than called because upstream
keeps =getApkFile ()= private; it uses =getPackageName ()=, never the
upstream hard-coded ="org.gnu.emacs"=.

** Why Emacs is the launcher

The product is "Emacs with a Unix environment", not "a terminal that
can run Emacs".  =EmacsActivity= keeps the single MAIN/LAUNCHER
intent filter; =TermuxActivity= loses its launcher/leanback filters
and =shortcuts= metadata but stays =exported=, reachable via an
explicit component intent:

#+BEGIN_EXAMPLE
am start -n tech.khalidrafi.emacshell.termux/com.termux.app.TermuxActivity
#+END_EXAMPLE

which is exactly what =M-x emacshell-open-terminal= does from Lisp
(Emacs 31.1 exposes no =android-start-activity= primitive; the
=android-*= Lisp surface is clipboard/notifications/directory access
only — see =src/android.c= / =src/androidselect.c=).  The command
prefers the bootstrap's =termux-am= over =/system/bin/am= because some
Android 12+ SELinux policies deny plain apps the execution of the
system =am= wrapper.

* First-boot flow

#+BEGIN_EXAMPLE
 install APK
     |
     v
 EmacshellApplication.onCreate
     |- write files/.emacs.d/early-init.el + init.el (if absent)
     |  [synchronous: EmacsActivity must not race these]
     v
 EmacsActivity (launcher) starts Emacs
     |  Emacs loads early-init.el:
     |    PATH/exec-path := <prefix>/bin : <old PATH>
     |    PREFIX := /data/data/<applicationId>/files/usr
     |    SHELL := <prefix>/bin/bash (when present)
     |  Emacs loads init.el:
     |    emacshell-open-terminal defined
     |    [distro] emacshell-distro-login defined
     v
 first activity resume
     |- TermuxInstaller.setupBootstrapIfNeeded (activity-scoped:
     |    progress + error dialogs need a window)
     |        |- libtermux-bootstrap.so (embedded zip, custom prefix)
     |        |     -> files/usr          (apt, bash, coreutils, ...)
     |        |- [distro] unpack the alpine-rootfs.tar.gz asset
     |              -> files/usr/var/lib/proot-distro/installed-rootfs/alpine
     v
 steady state: Emacs is the app; the environment is one M-x away
#+END_EXAMPLE

The init files are written ONCE and then belong to the user; upgrades
never touch them.

** The distro flavor rootfs

=proot-distro= (installed by the distro bootstrap) expects a
distribution at =$PREFIX/var/lib/proot-distro/installed-rootfs/<alias>=.
Rather than invoking =proot-distro install= (a shell script whose local
tarball semantics are undocumented and which would need prefix
binaries to have settled), =DistroRootfsStager= unpacks the bundled
tarball there directly, via a small streaming tar reader
(=TarExtractor=):

- extract into =installed-rootfs/alpine-staging=, =renameTo= on
  success — a killed process can never leave a half-rootfs under the
  final name;
- =bin/sh= existence is the activation test (and the idempotency
  test — staging is a no-op once installed);
- modes and symlinks are honored (=Os.chmod= / =Os.symlink=); hard
  links, device nodes and fifos are skipped (none occur in an Alpine
  minirootfs, and the app could not create them anyway);
- every entry path is canonicalized against the destination (zip-slip
  guard).

The tarball's integrity is established before it ever enters the APK:
sha256 pin in =pins/alpine-rootfs-aarch64.sha256=, verified by
=prepare-distro-rootfs.sh= (cross-checked against Alpine's own
=.sha256=) and re-verified by the Gradle build.

* The two flavors

| | termux | distro |
|---|---|---|
| applicationId | =tech.khalidrafi.emacshell.termux= | =tech.khalidrafi.emacshell.distro= |
| label | Emacshell (Termux) | Emacshell (Distro) |
| bootstrap | custom-prefix base set | same + =proot=, =proot-distro= |
| extra asset | — | =emacshell/alpine-rootfs.tar.gz= |
| init.el | =emacshell-open-terminal= | + the distro commands (see below) |
| first boot | unpack bootstrap | unpack bootstrap, then stage rootfs |

Flavor selection at runtime uses the applicationId (the single source
of truth the bootstrap binaries are compiled against), not a Gradle
constant smuggled through =BuildConfig=.

* Process and identity model

- One process, one UID, one data directory
  (=/data/data/<applicationId>/files=), shared by the Emacs GUI, the
  Termux terminal and every subprocess.  This is what upstream calls
  the "termux/ dance" and solves by hand; here it is true by
  construction.
- No =sharedUserId=: side-by-side installability is law (README.md).
  All component names that must be unique system-wide (provider
  authorities, custom permissions, intent actions) are derived from
  the applicationId via manifest placeholders.
- =targetSdk 28=, inherited from both upstreams: newer targets break
  background execution semantics a workstation-app depends on; the
  trade-off and its review status live in REVIEW.org.
- The GNU Emacs native libraries (=libemacs.so= and 37 companions) are
  the official GNU build, loaded via =System.loadLibrary= exactly as
  upstream does; =android:extractNativeLibs="true"= +
  =useLegacyPackaging= keep them on the filesystem where the Emacs
  loader expects them.

* The usage bridge (org-activity)

The Owner's order (2026-11-22): org-activity must reach full StayFree
/ ActivityWatch parity on Android, and "patch the Emacshell app if
necessary" — so the app answers, not an Emacs fork.  The constraint
set:

- The app's law is *No Emacs C rebuild, ever*; the Emacs Android port
  also exposes no generic Java interop, so no new Lisp primitive can
  exist without rebuilding ~libemacs.so~.
- The manifest already declares
  =android.permission.PACKAGE_USAGE_STATS= (inherited from termux-app),
  and Usage Access is a Settings flip, not a runtime dialog.
- Emacs and the app share the process AND the files dir — =HOME= for
  the Emacs Android port IS =getFilesDir()=.

=tech.khalidrafi.emacshell.EmacshellUsageServer= (started from
=EmacshellApplication.onCreate=) therefore binds =127.0.0.1= on an
ephemeral port and writes two files into the files dir:
=emacshell-usage-port= and =emacshell-usage-secret= — readable by
Emacs as =~/emacshell-usage-port= / =~/emacshell-usage-secret= (the
org-activity client's defaults), unreadable by any other app
(different UID, loopback is device-shared — hence the per-boot
secret gating every request).

Protocol: one line per request, one line of JSON per response, one
request per connection:

#+BEGIN_EXAMPLE
  STATS <secret> <begin-ms> <end-ms>
    -> {"granted":true,"apps":[{"package":...,"label":...,
         "lastUsedMs":N,"foregroundMs":N}]}          ; aggregate query

  EVENTS <secret> <begin-ms> <end-ms>
    -> {"granted":true,"events":[{"package":...,"type":"resume",
         "tsMs":N}]}   ; filtered stream: resume, pause, screen_on,
                         screen_off, keyguard_shown, keyguard_hidden,
                         notification_seen

  PING <secret> -> {"ok":true,"granted":BOOL}
#+END_EXAMPLE

=EVENTS= is what makes StayFree parity real: opens (resume counts),
unlocks (keyguard_hidden, screen_on fallback below API 30),
notification counts (notification_seen, API 29+) and the hour-of-day
timeline (resume→pause sessions) — the same signals StayFree itself
derives.  Honest limits: the keyguard/screen event types exist only
from API 30 and notification_seen from API 29; older devices simply
never emit them (documented in org-activity, not hidden here).

Failure discipline: the server thread is a daemon; any per-connection
exception is logged and dropped; a bind failure disables the bridge
for that boot.  Ungranted Usage Access returns
={"granted":false,"hint":...}= so the client can point the user at
Settings.  Nothing about the bridge runs a query unless Emacs asks —
battery cost is an idle =accept()=.

* What is deliberately NOT done

- No Emacs C rebuild, ever: the =-29= arm64 APK is the artifact of
  record (sha256-pinned, GPG-verified in CI).
- No background Termux service start at boot: the terminal runs only
  when asked for; Emacs keeps its own process alive.
- No automatic writes to the user's init files after first boot.
- The distro is a runtime CHOICE (Owner order 2026-11-23): the bundled
  alpine stays the only OFFLINE rootfs (first-boot staged), and
  =M-x emacshell-distro-install= fetches any other alias proot-distro
  knows over the network (debian, ubuntu, arch, fedora, opensuse,
  kali...).  =emacshell-distro-name= picks the default;
  =M-x emacshell-distro-list= shows what the installed proot-distro
  supports; =emacshell-distro-login= completes over the installed
  rootfs.  Everything runs through the SAME prefix's proot-distro, so
  the custom-prefix story is unchanged.
